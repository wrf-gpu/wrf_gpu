Namelist Compatibility

wrf_gpu reads a standard Fortran WRF v4 ARW namelist.input — all the usual groups (&time_control, &domains, &physics, &dynamics, &bdy_control, …). Bring your existing namelist. Before any expensive JAX import or compile, the port validates every gated physics/dynamics selection fail-closed: each option is either implemented, loudly refused with a named reason, or a documented out-of-scope decision. You never get a silent wrong answer from selecting a scheme the port has not wired.

The no-silent-gaps contract

Every unsupported namelist option is rejected before any compute, with a specific named reason and the operational swap to use — the port never silently substitutes or skips a scheme. These are boundaries and a roadmap, not hidden gaps. This is a WRF-compatible reimplementation validated against WRF as an oracle, not a bit-true Fortran port: expect operational (RMSE-class) agreement, not byte equality.

The fail-closed philosophy

The gpuwrf run CLI calls the operational namelist validator before any heavy import. A machine-readable catalog classifies every WRF v4 code of the gated parameters — mp_physics, cu_physics, bl_pbl_physics, sf_sfclay_physics, sf_surface_physics, ra_lw_physics, ra_sw_physics, and the dynamics options diff_opt, km_opt, damp_opt, diff_6th_opt, rk_order, w_damping, sf_urban_physics — against the full WRF v4 enumeration. Each selection resolves to exactly one of five honest statuses:

Operational vs Reference-only — the distinction that matters

A Reference-only scheme is a real, oracle-backed WRF scheme, but it is never part of an operational forecast. The base validation layer accepts it (for single-column / reference comparisons); the operational layer additionally rejects it. Refusing is the honest behavior: the operational scan cannot actually select it and would otherwise route through a missing kernel or run a different scheme than you asked for.

What a refusal looks like

Refusals are specific and actionable. For example, running gpuwrf run with ra_lw_physics=5 (GSFC/Goddard NUWRF longwave, a reference-only scheme):

physics.ra_lw_physics=5 (GSFC/Goddard NUWRF longwave): WRF v4
longwave-radiation scheme accepted only for reference/oracle work, but NOT
operationally wired into the GPU forecast scan. Running it would SILENTLY
use a DIFFERENT scheme than requested or route through a missing kernel --
refusing rather than producing a silent wrong-scheme run.
Operationally-wired ra_lw_physics values: 0, 1, 4. Action: Use
ra_lw_physics=4 (RRTMG, GPU-operational default) or 1 (classic RRTM).

Multi-domain columns (mp_physics = 8, 28) and the Fortran repeat-count syntax (mp_physics = 3*8 = three domains of 8) are both handled.

v0.23 updates to the classification

v0.23 extends the classification and is reflected in the current counts above:

  • New-Tiedtke cumulus (cu_physics=16) graduates to Operational — machine-precision JAX kernel vs a pristine-WRF single-column oracle. (Like Tiedtke cu=6, it needs active flux-form moisture advection so WRF RQVFTEN is available; see Dynamics.)
  • Morrison-aerosol microphysics (mp_physics=40) joins Reference-only with real oracle — the fp64 column kernel is proven to machine precision, but the prescribed AEROCU aerosol inputs have no operational State substrate yet.
  • NSSL 2-moment (mp_physics=18), CAM-UW PBL (bl_pbl_physics=9), urban BEP/BEM (sf_urban_physics=2/3) and the WRF lake model (sf_lake_physics=1) are Reference-only / Fail-closed with staged oracles; their faithful ports are tracked as their own milestones.

For the per-family option numbers of the operational menu, see Physics Options. The full per-code support table (every WRF v4 code → scheme name → status → note) lives in the repository at docs/namelist-compatibility.md.

Operational default suite

When a namelist does not pin a physics option, the dispatcher resolves to the validated baseline: mp_physics=8 (Thompson), bl_pbl_physics=5 (MYNN), sf_sfclay_physics=5 (MYNN surface layer), cu_physics=0 (no cumulus), sf_surface_physics=4 (Noah-MP). Radiation has no dispatcher default; the operational slot runs the selected SW + LW (default ra_sw_physics=4 / ra_lw_physics=4, RRTMG).

Mandatory WRF pairing enforced

MYJ PBL (bl_pbl_physics=2) ↔ Janjic-Eta surface layer (sf_sfclay_physics=2) must be selected together (or neither as 2). Selecting exactly one as 2 fails closed both at validation and in the dispatcher.

The validator checks selections, not completeness

The catalog validates the selected physics/dynamics options. It does not (yet) validate non-physics consistency such as timestep CFL, domain ratios, or IO intervals — those remain your responsibility. See also Dynamical Core for the numerics options and Physics Options for the full operational scheme menu.

Evidence, clocks and limitations.

wrf_gpu is validated by a reproducible, CPU-only identity-proof system that compares a GPU wrfout against a CPU-WRF wrfout from the same initialization, over all grid cells, all forecast leads, and all core prognostic variables, against a frozen tolerance manifest that is read before comparison and never tuned. WRF is the oracle; this is the project's primary fidelity gate.

The cell-identity method

Cell-identity is a per-cell, per-lead, per-variable proof — not an aggregate station-RMSE summary. For a matching GPU/CPU pair it scores every field at every grid cell and every forecast hour against a limit fixed in advance. A field is green only if it stays inside its frozen tolerance everywhere; a field that breaches is drawn red and carried honestly — the limit is never widened to paint it green. Full method and reproduce commands are in docs/IDENTITY_PROOF.md in the repository.

Why not bitwise equality?

Bit-for-bit reproduction of a specific WRF build is impossible across compilers and MPI rank counts (WRF is not bit-identical to itself under those changes). wrf_gpu instead proves cell-for-cell agreement within a frozen physical tolerance — a stronger, more meaningful claim for a rewrite than chasing one compiler's rounding.

The v0.18 red field — RAINNC — in plain terms

The single out-of-envelope field is accumulated precipitation RAINNC (5.22 mm vs a tight 1.0 mm bound over 72 h). Its physics is correct — the individual rain / ice / snow processes match WRF to ~1e-7 (oracle-green). What does not close to the 1.0 mm bound is the accumulated total: precipitation placement is the most chaotically-sensitive field in any weather model, so legitimate differences down to floating-point operation order move a shower a grid cell over, and summed over 72 h that grows to a few-mm cell-by-cell difference. RAINNC is a derived running counter that does not feed back into the forecast; the prognostic fields that drive skill — wind, temperature, and moisture (QVAPOR, which passes) — are all within tolerance. It is drawn red and carried, not painted green.

Default numerics across releases

The stability > identity priority does not forbid a real correctness repair. v0.23.4 intentionally changes results relative to v0.23.3: it restores WRF moist/scalar transport ordering and balances Thompson ice mass/number before sedimentation. Ice-sensitive trajectories must therefore be revalidated or rebaselined; no cross-release byte-identity claim is made. For historical context, v0.23 was numerically equivalent to v0.22.2:

  1. The dynamical core is untouched — net dynamics diff v0.22.2→v0.23 is 0 lines.
  2. The only default-on changes to the compiled program (P0 radiation flux-slice, P3 flat-2-dom fusion) are proven CPU bit-identical (sha256 before==after).
  3. With XLA autotune held fixed (same-cache control) the default path is bit-identical to v0.22.2 (max_abs 0.0, 0/178 leaves).
  4. Across two independent cold compiles it matches v0.22.2 within the autotune floor — a self-control confirms the v0.23-vs-v0.22.2 field differences over the 1 h canary are indistinguishable from v0.22.2 differing from its own second cold compile.

The only difference is the same run-to-run GPU autotune nondeterminism v0.22.2 already exhibits against itself. No masking, clamps, or nan_to_num.

Reproduce it yourself

The identity proof is CPU-only and never touches the GPU. Given a matching CPU/GPU wrfout pair:

python3 scripts/build_identity_proof_plots.py \
  --cpu-dir "$CPU_DIR" --gpu-dir "$GPU_DIR" \
  --domain d01 --init "2023-01-15T00:00:00+00:00" \
  --case-id switzerland_d01_72h --region-label "Switzerland d01 72h" \
  --tolerance-json proofs/v014/grid_delta_atlas/tolerance_manifest_candidate.json \
  --proof-dir  proofs/<case>/identity_proof \
  --asset-dir  docs/assets/<case>/identity_proof

Every claim on this page has a proof object under proofs/ in the repository, and the equivalence demo (scripts/equivalence_demo.py) and reproducibility harness (scripts/verify_reproducibility.sh) run on CPU. See also docs/VALIDATION.md and docs/REPRODUCIBILITY.md.

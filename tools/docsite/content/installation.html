Installation & Requirements

wrf_gpu is a JAX/CUDA application: a CUDA-capable NVIDIA GPU, a CUDA 13 JAX build, and Python. This page covers the hardware you need, the full and the minimal (source-only) install, how to verify the GPU is visible, and the runtime-table environment variable that table-using physics schemes require before a run.

The short version

pip install --upgrade "jax[cuda13]", then pip install -e . (or pip install -e ".[cuda]"), then python -c "import jax; print(jax.devices())" to confirm a CUDA device. Set GPUWRF_WRF_ROOT before running any case that selects Noah-MP or classic RRTM. Jump straight to the Quickstart once jax.devices() lists your GPU.

GPU & VRAM sizing

The reference machine is a single RTX 5090 (32 GiB) workstation; the numbers below are Measured on it. Peak VRAM is transient working memory (largest during the radiation transient and the cold start), not the persistent fp64 model state — so it scales with grid size and physics, not with forecast length.

CasePeak VRAMNotes
d01 9 km single domain≈ 4.7 GiBBundled-class single-domain forecast.
1 km single domain18.25 GiBFits one RTX 5090 bit-identically (chunked BouLac cold start).
1 km all-island nested (9/3/1; d03 520×280×45, ~145k columns)~18.1 GiBFits the reference card; earlier releases OOMed near 31.8/32 GiB.
Switzerland d01, 72 h identity gate22.9 GiBRetained 72 h validation run.
Canary L2 d02, nested 72 h identity gate29.8 GiBRetained 72 h nested validation run.

As a rule of thumb, a 3 km d02 fp64 case wants ≥ 26 GiB free VRAM. Nested runs (--max-dom > 1) additionally run a launch-time VRAM preflight and fail closed unless the card has at least max(24 GiB, 0.50 × total VRAM) free — see the VRAM preflight.

High resident host RAM (~36 GB)

A run currently holds about 36 GB of host (CPU) RAM resident, even when VRAM use is only ~9.6 GB, because the Noah-MP / physics constant tables are baked into the compiled executable rather than passed as runtime arguments. This is precision-independent and does not affect correctness, single-run stability, or results — but it limits running two instances on a 64 GB box and reduces large-grid / pod-density headroom. It is root-caused; the tables-as-runtime-args fix is deferred.

Full install

Use an isolated environment. Python 3.11 is the reference interpreter; the package requires Python ≥ 3.10. Install the CUDA build of JAX first, then the package.

git clone https://github.com/wrf-gpu/wrf_gpu.git
cd wrf_gpu

# Isolated environment (venv or conda both work):
python -m venv .venv && . .venv/bin/activate
# or:  conda create -n wrfgpu python=3.11 && conda activate wrfgpu

# 1. GPU build of JAX (CUDA 13 wheels):
pip install --upgrade "jax[cuda13]"

# 2. wrf_gpu itself (pulls numpy, netCDF4, xarray, PyYAML, zarr, ...):
pip install -e .

# 3. Verify JAX sees the GPU (should list a cuda device):
python -c "import jax; print(jax.devices())"

Equivalently, the cuda extra pins the CUDA 13 jaxlib for you:

pip install -e ".[cuda]"
CUDA 12 host, or a resolver miss

On a CUDA 12 host use jax[cuda12] instead of jax[cuda13]. If the stable CUDA wheel does not resolve for your CUDA/driver combination, the JAX nightly CUDA wheel is the documented fallback. A plain pip install -e . pulls in CPU JAX, so the import and namelist-validation paths work without a GPU — but GPU execution needs the CUDA jaxlib.

Minimal source-only install

You do not need the whole repository (proofs, agent infrastructure, validation corpora) just to run wrf_gpu. A cone sparse-checkout of src plus the vendored runtime data tables is enough; this path was verified end-to-end on a clean machine.

# Shallow, no-checkout clone, then cone-sparse-checkout only what `run` needs:
git clone --depth 1 --no-checkout \
    https://github.com/wrf-gpu/wrf_gpu.git wrf_gpu && cd wrf_gpu
git sparse-checkout init --cone
# In cone mode the root files (pyproject.toml, README.md, LICENSE_NOTES.md) come
# automatically; add the source package and the vendored runtime data tables
# (the Thompson/RRTMG tables are loaded at import -- `src` alone is not enough):
git sparse-checkout set src data/fixtures
git checkout

# Install (CPU import works without a GPU; add the CUDA jaxlib to run on GPU):
python -m venv .venv && . .venv/bin/activate
pip install -e .                  # CPU import-check; or:
pip install -e ".[cuda]"          # GPU execution (CUDA 13 jaxlib)

# Verify:
python -c "import gpuwrf; print('wrf_gpu', gpuwrf.__version__)"
python -m gpuwrf.cli run --help   # the CLI is the entrypoint

The data/fixtures/ tables (~147 MiB) are required at import, so the sparse checkout must include them alongside src.

Prerequisite environment variables

Table-using schemes (Noah-MP and classic RRTM, plus WRF-table-dependent options) load lookup tables from a pristine WRF v4 install at runtime, so their paths must be set before you run a case that selects them. Without GPUWRF_WRF_ROOT, those schemes fail closed with a clear named error before any compute — they never silently substitute a scheme. Cases whose physics menu does not use those schemes run without it.

VariableRequired forWhat it points to
GPUWRF_WRF_ROOTNoah-MP, classic RRTM, WRF-table-dependent optionsRoot of a pristine WRF v4 source/run tree — provides the classic RRTM .F source and run/ tables (including Noah-MP tables and run/CCN_ACTIVATE.BIN for aerosol-aware Thompson).
GPUWRF_CANAIRY_ROOTThe validation corpusThe met_em / run-corpus root for the validation cases (run inputs + CPU-WRF reference). Not needed for the bundled example.

Two optional paths (both defaulted) tune performance and scratch:

GPUWRF_TMPDIR~/.cache/gpuwrfScratch root for transient files.

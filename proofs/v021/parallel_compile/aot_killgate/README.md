# AOT KILL-GATE harness

Proves (or KILLS) AOT PJRT-executable serialization on a **real** de-fuse
`_advance_chunk_fori` module — the one unproven claim the AOT compile-wall fix
rests on. The cross-domain-parallel-compile workflow only proved
serialize/deserialize on TOY modules; this closes the gap on a real
RRTMG-SW+LW + Noah-MP body. The machine-readable verdict this harness emits is
`out/killgate_verdict.json` (regenerated by running the two scripts below; see
"Manager run commands").

Two scripts, run **in two FRESH processes**:

1. `serialize_one.py` — builds ONE real single-domain `_advance_chunk_fori`
   (bigswiss `d01`, tiny `n_steps` → ~minutes compile, NOT the ~50 min 9-nest),
   compiles it, `serialize()`s the PJRT executable, and writes the blob + meta
   (`in_tree`/`out_tree`/`in_avals`/fingerprint/concrete inputs) to `out/`.
   Prints: compile wall, blob size (bytes / MB), cache-entry delta.

2. `deserialize_run.py` — **FRESH process**: reads the blob + meta,
   `dev.client.deserialize_executable(blob, DeviceList((dev,)), None)`, selects
   the EXACT runtime buffers via the saved `kept_var_idx` (see below), executes
   on the SAME saved inputs, then builds a FRESH normally-`jax.jit`-compiled
   reference of the same module and byte-compares every output array.
   Prints: deserialize wall, execute wall, `BYTE_IDENTICAL=True/False`
   (+ per-array `max_abs_diff` if not). Writes `out/killgate_verdict.json`.

### The `kept_var_idx` runtime-buffer fix (the 130-vs-123 issue)

XLA const-folds / DCEs some inputs at compile time, so the executable expects
FEWER runtime buffers than a naive `tree_flatten` supplies (the first GPU gate hit
`Execution supplied 130 buffers but compiled program expected 123` — XLA dropped 7
inputs). JAX's own executor keeps only the indices in `kept_var_idx`
(`pxla.py:373`: `args = [x for i, x in enumerate(args) if i in self.kept_var_idx]`).
`serialize_one.py` reads `compiled._executable._kept_var_idx` (fallback
`unsafe_call.kept_var_idx`) and persists it; `deserialize_run.py` supplies exactly
`[in_flat[i] for i in kept_var_idx]` (in order), replicating JAX's convention.
If `kept_var_idx` cannot be captured (jax API drift), the consumer falls back to a
naive flatten and the buffer-count mismatch surfaces clearly rather than guessing.
`serialize_summary.json` reports `expected_runtime_buffers` / `dropped_input_leaves`;
the verdict reports `supplied_runtime_buffers` vs `expected_runtime_buffers`.
(Validated on CPU on a synthetic module that drops 7 of 10 leaves: the kept-filtered
execute is byte-identical.)

## KILL conditions

- `BYTE_IDENTICAL=False` on the real module → **AOT is dead**.
- Deserialize wall large / memory-heavy → erases the warm win (manager judges vs
  the ~30 min re-lower it replaces).

`serialize_one.py` exits non-zero if the API attrs are missing (jax API drift);
`deserialize_run.py` exits non-zero on a failed deserialize/execute or a
non-byte-identical result, and warns (fail-closed semantics) on a fingerprint
mismatch.

## Manager run commands (under the GPU lock)

Run from the worktree root `<USER_HOME>/src/wrf_gpu2_wt/parallel-compile`.
`scripts/with_gpu_lock.sh` lives in the **main** repo — adjust the path to your
checkout if needed; the example assumes the main checkout at
`<USER_HOME>/src/wrf_gpu2`.

```bash
WT=<USER_HOME>/src/wrf_gpu2_wt/parallel-compile
LOCK=<USER_HOME>/src/wrf_gpu2/scripts/with_gpu_lock.sh
KG=$WT/proofs/v021/parallel_compile/aot_killgate

# 1) SERIALIZE (fresh process, GPU)
"$LOCK" --label aot-killgate-serialize -- env \
  PYTHONPATH="$WT/src" JAX_ENABLE_X64=true GPUWRF_FORCE_FP64=1 \
  python "$KG/serialize_one.py"

# 2) DESERIALIZE + EXECUTE + byte-compare (SEPARATE fresh process, GPU)
"$LOCK" --label aot-killgate-deserialize -- env \
  PYTHONPATH="$WT/src" JAX_ENABLE_X64=true GPUWRF_FORCE_FP64=1 \
  python "$KG/deserialize_run.py"
```

A GO is: step 2 prints `BYTE_IDENTICAL=True` with a small deserialize+execute
wall (seconds), and `out/killgate_verdict.json` has `"BYTE_IDENTICAL": true`.

## Env knobs (defaults work out of the box)

| var | default | meaning |
|---|---|---|
| `AOTKG_INPUT` | `<DATA_ROOT>/wrf_gpu_validation/v017_bigswiss_gpu_init` | wrfinput run dir for `build_replay_case` |
| `AOTKG_DOMAIN` | `d01` | domain label |
| `AOTKG_N_STEPS` | `2` | traced loop count (keep tiny → fast compile) |
| `AOTKG_RADT_STEPS` | `100` | radiation cadence steps |
| `AOTKG_DT_S` | `18.0` | timestep seconds (d01 3 km) |
| `AOTKG_OUT` | `<this dir>/out` | artifact dir (must match across the two scripts) |
| `AOTKG_SKIP_FRESH_REF` | `0` | `1` → compare only vs the saved `out_ref_host` (skips the second real-State build; weaker but cheaper) |

**Both scripts must use the SAME env** (`AOTKG_*`) so the fresh reference rebuilds
the identical real carry. They are env-parametrized + defensive: a missing API
attr or input dir prints a clear error and exits non-zero rather than tracebacking.

## CPU note

On CPU, `serialize()/deserialize()` round-trips and is byte-identical, but XLA:CPU
logs a `machine type ... doesn't match ... SIGILL` warning (host CPU-feature
mismatch) — exactly the target-pinning hazard the fingerprint guard exists for.
The real gate is the **GPU** run, where the same-device fingerprint matches.

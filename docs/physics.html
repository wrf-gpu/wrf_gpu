Physics Options

wrf_gpu dispatches a wired menu of WRF physics schemes, selected exactly as in WRF — by the same namelist.input integer keys (mp_physics, bl_pbl_physics, cu_physics, ra_lw_physics / ra_sw_physics, sf_sfclay_physics, sf_surface_physics). Anything outside the wired menu fails closed before any compute with a named reason — it is never silently swapped for something else.

How to read the status

Operational = scan-wired into the GPU forecast loop and WRF-oracle-gated. Reference-only = a real WRF scheme with a validated oracle, but not wired — selecting it operationally fails closed. Out of scope = a documented architecture boundary. The wiring lives in src/gpuwrf/runtime/operational_mode.py and src/gpuwrf/coupling/scan_adapters.py; the accepted matrix in src/gpuwrf/contracts/physics_registry.py.

Table-loading schemes need GPUWRF_WRF_ROOT

Noah-MP, classic RRTM, and WRF-table-dependent options load lookup tables from a pristine WRF v4 tree at run time. Point GPUWRF_WRF_ROOT at that tree before selecting them, or they fail closed with a clear named error. Cases whose menu does not use those schemes run without it. See Installation → Prerequisites.

Diffusion, gravity-wave drag & urban/lake¶

  • Horizontal diffusion (diff_opt, km_opt): constant-K and 2-D Smagorinsky including terrain-slope and map-factor deformation terms (WRF formula parity, max residual 3.78e-15). 3-D TKE / full Smagorinsky (km_opt=2/3/5) is fail-closed — use km_opt=1 or 4. See Dynamical Core.
  • Gravity-wave drag (gwd_opt=1): default-on on the nested 1 km path (GPUWRF_GWD_NESTED=0 forces it off).
  • Urban (sf_urban_physics=2/3, BEP/BEM) and lake (sf_lake_physics=1): Reference-only / fail-closed with staged oracles (default sf_urban_physics/sf_lake_physics=0).

Every WRF v4 scheme is classified¶

No WRF v4 scheme is silently dropped. Every one is classified into exactly one bucket — the integrity of this partition (State = 67 leaves, no clobber) is itself a proof object:

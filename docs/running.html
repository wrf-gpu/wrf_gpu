Running the Model

Everything a forecast needs goes through one command: python -m gpuwrf.cli run. It validates your namelist fail-closed, auto-detects whether to run standalone native-init or CPU-WRF replay, advances the forecast on the GPU, and writes WRF-compatible wrfout history plus a run-payload JSON. This page is the complete flag reference and the mode map.

The gpuwrf run command¶

Run python -m gpuwrf.cli run --help for the authoritative list on your build. Every flag:

FlagDefaultMeaning
--input-dirrequiredRun directory holding the case inputs. Standalone native-init when it has wrfinput_<domain> + wrfbdy_d01 but no CPU-WRF wrfout; CPU-WRF replay when it has ≥ 2 wrfout_<domain> history files (auto-detected).
--output-dirrequiredDirectory for the generated wrfout files and the run payload.
--namelist<input-dir>/namelist.inputWRF namelist.input to validate fail-closed before the run. Defaults to the case's own namelist.
--domainnamelist → d01Domain id for a single-domain run. New in v0.23.1: when omitted it resolves to the root domain d01 (WRF's default) instead of the old d02; an explicit value always wins. Ignored when the run is nested (max_dom > 1): all domains d01..dN run together.
--max-dom1Number of nested domains to run (d01..dN). 1 = single-domain on --domain. Set > 1 to run the standalone live-nested driver (parent feeds each child's lateral boundary live; no CPU-WRF wrfout).
--domains-from-namelistoffNew in v0.23.1. Run all domains the namelist declares (its max_dom) — the explicit WRF-parity nested path. Conflicts with --max-dom.
--hoursnamelist → 1Forecast hours to advance. New in v0.23.1: when omitted it is read from the namelist &time_control (run_days/run_hours/run_minutes/run_seconds), falling back to 1 if absent; an explicit value always wins and is announced.
--dry-runoffNew in v0.23.1. Validate the namelist, detect the input mode, resolve hours/domain/max_dom/scratch, print the effective plan, and exit without compiling or running.
--scratch-dir<output-dir>/.scratchDisk-backed scratch for transient NetCDF/diagnostics — never /tmp tmpfs. $GPUWRF_SCRATCH overrides. Cleaned up on exit.
--proof-dir<output-dir>/proofsDirectory for the proof JSON.
--compare-cpu-dirnoneCPU-WRF reference directory for a dimension compare. If omitted, no dimension compare runs. Writes <proof-dir>/dimension_compare.json.
--scoreoffAlso score against AEMET station observations (needs GPUWRF_AEMET_ROOT; not part of the README runnability gate).
--feedbackoffNested runs only: enable two-way nesting. Default off (one-way).
--force-gpu-runoffNested runs only: bypass the GPU lock / free-VRAM preflight. Also available as GPUWRF_FORCE_GPU_RUN=1.

The command prints one JSON payload to stdout and exits non-zero on any blocked/partial/dimension-fail result (and exit 75 when the nested VRAM preflight fails closed).

WRF-parity defaults (v0.23.1)

Like WRF's wrf.exe, omitted runtime choices are read from namelist.input: forecast length from &time_control and the single-domain --domain from the root domain d01. The resolved values (and whether each came from a flag, the namelist, or a default) are printed and recorded in the run payload (effective_hours, effective_domain, effective_max_dom, override_sources). An explicit flag always overrides. Use --dry-run to preview the effective plan before compiling. See the WRF-parity roadmap.

Check scheme support offline — gpuwrf namelist-support¶

New in v0.23.1. Print which namelist scheme values are operational, reference-only, fail-closed, or disabled — without importing JAX or touching the GPU, so it is instant:

python -m gpuwrf.cli namelist-support          # human-readable table
python -m gpuwrf.cli namelist-support --json    # machine-readable

Use it to check whether your namelist.input physics selections will run before you start a forecast. See Namelist Compatibility and Physics Options.

Replay vs. standalone native-init (auto-detected)¶

You never pick the init mode by hand — run detects it from the --input-dir contents and announces which path ran:

Detected when the input dir has…ModeWhat it does
WRF real-data artifacts — wrfinput_<domain> + wrfbdy_d01, no CPU wrfoutstandalone native-initLoads the initial state from wrfinput, lateral boundaries from wrfbdy, and integrates on the GPU — no CPU-WRF wrfout dependency. The primary path.
≥ 2 CPU-WRF wrfout_<domain> history filesCPU-WRF replayTakes the initial state and boundaries from the existing CPU-WRF history — the legacy skill-comparison path.

See Input Data & Initialization for how each mode reads its inputs.

Single-domain vs. nested¶

Nesting is explicit opt-in via --max-dom N. A multi-domain namelist (max_dom > 1) does not silently become a nested run: without --max-dom, run executes a single domain (--domain) and prints a note reminding you to pass --max-dom N for the live-nested forecast. With --max-dom > 1, the standalone live-nested driver runs d01..dN together, the parent building each child's lateral boundary live (no pre-supplied wrfbdy_d02). Mechanics: Nesting.

Restart¶

wrf_gpu supports the standard WRF restart mechanism as part of its initialization path — restart is bit-identity-validated, and the per-domain subcycling nested path supports it as well. Restart cadence is governed by the usual namelist.input keys (restart, restart_interval); the restart file carries the WRF-faithful state (for example the 1 km inner-nest qke cold-start seed) so a restarted run picks up where it left off.

Two-way nesting (--feedback)¶

Opt-in For nested runs, --feedback enables two-way nesting: after each child finishes its subcycle, its interior is fed back onto the overlapping parent cells (WRF copy_fcn area-average plus the sm121 feedback-zone smoother). The default is one-way nesting — the validated wiring. Two-way feedback is finite and stable but its 24 h skill equivalence is untested, so it is off by default.

Station scoring (--score)¶

--score additionally scores the forecast against AEMET station observations. It requires GPUWRF_AEMET_ROOT and is not part of the README runnability gate — leave it off for a plain forecast.

VRAM preflight & --force-gpu-run¶

For nested runs (--max-dom > 1) the CLI runs a fast, CPU-side VRAM-headroom preflight before the (multi-minute) compile and fails closed with exit 75 instead of OOMing tens of minutes in. The default free-VRAM threshold is card-relative: max(24 GiB, GPUWRF_MIN_FREE_VRAM_FRACTION × total VRAM) with GPUWRF_MIN_FREE_VRAM_FRACTION=0.50. Tune it with:

KnobEffect
GPUWRF_MIN_FREE_VRAM_FRACTIONCard-relative threshold (default 0.50).
GPUWRF_MIN_FREE_VRAM_GIBExplicit GiB threshold override.
--force-gpu-run / GPUWRF_FORCE_GPU_RUN=1Deliberate operator override — bypass the lock/preflight entirely.
Prefer thresholds over the bypass

The preflight exists to stop co-resident JAX/GPU jobs from shrinking the RRTMG radiation-transient headroom at launch. Prefer the threshold knobs for tuning; reserve --force-gpu-run for a deliberate operator override.

Example invocations¶

1. Bundled single-domain Switzerland case (see the Quickstart):

export GPUWRF_WRF_ROOT=/path/to/WRF
python -m gpuwrf.cli run \
    --input-dir   examples/switzerland_d01 \
    --output-dir  runs/switzerland_d01 \
    --domain      d01 \
    --hours       1 \
    --scratch-dir /fast/nvme/scratch

2. Your own single-domain case, explicit namelist and domain:

python -m gpuwrf.cli run \
    --namelist    /path/to/case/namelist.input \
    --input-dir   /path/to/case \
    --output-dir  runs/my_forecast \
    --domain      d02 \
    --hours       24 \
    --scratch-dir /fast/nvme/scratch

3. Live-nested d01→d02→d03, 24 h:

python -m gpuwrf.cli run \
    --input-dir   /path/to/case \
    --output-dir  runs/nested \
    --max-dom     3 \
    --hours       24 \
    --scratch-dir /fast/nvme/scratch

4. Replay + dimension-compare against a CPU-WRF reference:

python -m gpuwrf.cli run \
    --namelist        /path/to/case/namelist.input \
    --input-dir       /path/to/case \
    --output-dir      runs/cmp \
    --domain          d02 \
    --hours           1 \
    --compare-cpu-dir /path/to/case

This writes runs/cmp/proofs/dimension_compare.json and exits 0 only on a clean pipeline and a dimension PASS.

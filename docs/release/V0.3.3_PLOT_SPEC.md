# v0.3.3 hourly deviation plots — pre-registered 2026-10-06

Scope: every 72 h validation case (six Tenerife twins, eight problem days,
Monica), every available domain, original CPU-WRF versus the corresponding
GPU run. The first prototype uses RC33P 0227 (`70d3374c7`); it is not a
final-release validation claim. Preserve the per-hour × variable colour
heatmap and add PNG line figures and an HTML gallery with the plotted JSON.

## Pairing, statistics and limits

- Reuse `scripts/release_plots/wrfout_pairs.py` to pair each domain's files by
  nominal valid hour. Require exactly τ0…72, reject duplicate hours, check
  internal `Times` against the filename, and record any seconds offset.
  Require matching variable dimensions and shapes. No interpolation,
  destaggering, terrain/land/sea/boundary masks, subsampling or outlier removal.
- For each field, hour and domain, read **every** stored cell in both operands
  with automatic NetCDF masking disabled. Reject any NaN or ±Inf in either
  complete operand **before** statistics (E200); retain finite fill values.
  Compute differences and reductions in float64; do not alter source files.
  Difference δ = GPU − original CPU-WRF. Mean bias = mean(δ),
  RMSE = sqrt(mean(δ²)); all cells have equal weight on their native grid.
- Spatial bands describe |δ|, not uncertainty in the mean: dark p25–p75,
  light p5–p95, NumPy `quantile(method="linear")`, over the same complete
  domain/vertical/staggered array. Plot RMSE and the two bands on the upper
  axis, signed mean bias on the second axis, RMSE/CPU-pair RMSE on a third
  axis with reference lines 1 and 2 (pair/RC ≥0.5 corresponds to ratio ≤2).
  Missing/zero pair denominators are explicitly undefined, with no artificial
  floor. Keep all excursions visible. One shared legend per figure sits
  outside the axes; titles identify the measured model tree hash.
  Caption: ratio >2 at small absolute error is expected where the CPU pair is
  near zero (early leads, d01); the 50% rule applies only to D6 exceedance frames.
- Fields: T2 [K], PSFC [Pa], U10/V10 [m/s], accumulated RAINNC [mm], hourly
  RAINNC increment [mm], T [WRF perturbation potential temperature, K],
  U/V/W [m/s], QVAPOR [g/kg; values and limits converted from kg/kg ×1000].
  Hourly rain at τh = RAINNC(h)−RAINNC(h−1) in each run, without clipping
  negative increments. τ0 has no preceding hour: its increment is explicitly
  unavailable, not assigned zero. τ1…72 must all be present and finite.
- Dashed RMSE limits come byte-for-byte from the frozen D6 manifest
  `proofs/v014/grid_delta_atlas/tolerance_manifest_candidate.json` (SHA
  captured with the run). No new gate or relaxed threshold. Hourly rain has
  no separately frozen D6 limit: show the accumulated RAINNC limit as a
  clearly labelled **reference only**, and label its plot informational.
  Upper-axis maximum = 1.15 × max(spatial p95, GPU/CPU RMSE, pair RMSE).
  A higher D6 line is replaced by a visible off-scale arrow and numeric label,
  so the limit never compresses the curves into a small part of the panel.
  Mark every frozen D6 RMSE exceedance on the RMSE line; preserve its named
  validation classification separately, without changing any plotted value.
  The bias panel has a zero reference; the RMSE limit is not a bias gate.
- Keep the colour heatmap for the ten independently D6-bounded fields as
  RMSE/frozen limit, with marked exceedances; hourly rain appears separately
  as an informational increment panel. No pooled pass may hide a lead failure.

## Predictability and case summaries

Where a CPU initial-condition perturbation pair or IC-perturbed GPU pair is
available, compute its per-hour, per-domain, per-variable RMSE with the same
full-array finite-first rules. Plot a grey line of the same width as GPU/CPU RMSE,
labelled by pair provenance. A single pair is an empirical spread reference,
not a confidence interval or a gate waiver. Missing pair hours remain absent
and are reported explicitly; do not extrapolate them or drop GPU/CPU hours.
For the 0227 prototype, use original CPU-WRF versus P0227 (θ ±2⁻¹⁵ K)
where P0227 has completed; source manifests identify the exact pair.
The extractor defaults to `--pair-reference cpu` (original CPU vs its CPU
IC member). For a GPU IC member, use `--pair-reference gpu`: its spread is
the main GPU vs that member, **not** the original CPU vs the perturbed GPU.
The grey-line legend identifies which pair type supplied the spread.

For each variable and domain, a summary panel shows all cases' hourly RMSE
lines, their equal-case-weight mean at each lead, and mean ± one sample
standard deviation across cases (`ddof=1`), plus the frozen D6 dashed line.
The binding release page includes an all-cases summary per domain. Do not pool grid cells from
different cases or collapse the lead axis. Case counts and the included case
list are explicit; a one-case prototype has no estimable cross-case standard
deviation, so no artificial zero-width SD band is shown. Bias summaries use
the same definition when included. A completed release summary requires all
declared cases; partial delivery is labelled partial with the missing cases.

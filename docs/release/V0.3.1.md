## Parallel throughput [M]

The WN3 three-nest Tenerife sweep used six-hour runs on one RTX 5090, RC3's
unchanged model, the shipped launcher, fused C-auto and one retained autotune pin.
The CPU-WRF 3×4-core throughput reference is 123.4 s/case-hour.

| N | Whole-run aggregate s/case-forecast-hour | CPU throughput ratio | Launcher-wall s/case-hour |
|---|---:|---:|---:|
| 1 | 13.67 | 9.0× | 14.28 |
| 3 | 8.20 | 15.0× | 8.46 |
| 4 | 7.77 | 15.9× | 7.99 |

The whole-run aggregate is the first case process start to the phase's last
history file, divided by N×6 forecast hours. **Six-hour runs include per-case
init/load; no `--compress` was used (v0.3.0 FINAL-b R4 used it).** There is no
24-hour or energy extrapolation. Against FINAL-b R4's separate launcher-wall
rates of 16.63/9.63/9.68, the measured reductions are approximately
14%/12%/17.5%; the compression difference prevents attributing the entire change
to model kernels.

Warm per-case GPU allocation is 5,354 MiB (5.23 GiB), reported host VmHWM about
6.1 GB; host MemAvailable never fell below 50.4 GB. N=3 and N=4 were admitted
together at phase start and all cases returned rc 0. The common 0227 case has
21/21 identical file hashes across concurrency levels, a regression check.
[Selected sweep receipt](evidence/v031/parallel_sweep_selected.json) preserves
the exact clocks, admission decisions, resource samples and original source hash.

## Energy accounting

The timestamped V31 board-power logs are integrated inside the observed first-start
to last-history window by the E158 trapezoid rule. N=1/3/4 board costs are
2.863/2.571/2.557 kJ/case-forecast-hour [M]. Covered sample spans are 81/146/185 s,
maximum gaps two seconds; unlogged tails are 1.009/1.615/1.587 s and excluded.
Atlantic/Canary local timestamps are converted to UTC for the run date.
[Retained samples](evidence/v031/energy_samples.json) allow independent recomputation.

CPU energy is 200 W × 123.4 s = 24.68 kJ/case-hour [I], using owner-reported power
for the twelve-core CPU-WRF run; no package-power boundary is asserted. GPU host
share is assumed 4/12 × 200 W = 66.67 W [I]. Board plus host scenarios are
3.774/3.118/3.075 kJ/case-hour [I]. Board samples are measured, host shares and
combined comparisons are inferred, and no whole-node energy result is claimed.
The unclocked PROD log can support only a nominal-rectangle estimate [I], not
an E158 timestamped measurement; it is not used for the main energy chart.

## Exact regression controls, distinct from CPU fidelity

The restart control/resume check preserves 2,262 variables in six files. The
writer-only RC3 check retains all six Canary file hashes. In 50 Swiss January
files, every non-target variable/cell, all dimensions and global attributes are
unchanged relative to RC2. The intended glacier fields use CPU-WRF's undefined
sentinels; all 50 complete CPU frames match the changed values. The
[full writer check](evidence/v031/w01_identity_swiss_0115_full.json) records zero
violations, distinct from the numerical comparison.
These GPU-to-GPU controls establish regression scope, not independent fidelity.

## Output-integrity disclosures

Raw strict reports remain available. Their registered exceptions are:

- **R2:** negligible ice/snow traces; GPU-zero frames where the original CPU
  amplitude is at or below the registered 1e−9 threshold.
- **R4:** canopy-water-family onset/decay timing in a small number of frames.
- **R5:** canopy-ice and ground-snow threshold timing on frost cells. The
  Tenerife d03 raw report includes CANICE in three of 25 frames and QSNOWXY
  in four of 25; the causal classification does not remove those flags.

Glacier undefined-value conventions are a writer fix, not a new exception class.
The dedicated glacier runtime remains unported; tolerance agreement on a whole
domain does not establish every glacier process individually.

## Compile/performance limits

The conservative executable scan passes the hard stack criterion (PROD maximum
32 B, Swiss 64 B). Accepted large column/transpose flags remain documented; this
is not a claim that the conservative scan is flag-free. Matching field-310 checks
bind runtime executables to the retained autotune pin.

Eight conservative E41 kInput flags are runtime-bound on those PROD executables: maximum 0.049 ms, ordinary-root sum 0.213 ms, STACK 32 B (compile acceptance, 2026-10-05 08:32Z); [selected runtime evidence](evidence/v031/e41_runtime_selected.json) retains the exact program scope and measurements.

Three small Pallas auxiliary programs can receive new persistent-cache keys when
the installation path changes. The observed programs were force-down/coupled
updates and two BouLac helpers; zero timestep programs recompiled in the writer-only
RC3 comparison. Path-specific backend configuration is the current explanation [I].
Nested-domain layout variation and default-off EOS pruning remain performance
research items, not enabled unvalidated optimizations.

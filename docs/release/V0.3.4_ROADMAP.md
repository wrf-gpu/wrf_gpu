# v0.3.4 owner priorities — future plan

This ordered plan follows the owner roadmap of 2026-10-07. It adds no current
capability or v0.3.3 gate closure. Its implementation contracts start after
v0.3.3 publication; earlier measured residual notes are retained below.

| Order | Planned outcome | Qualification |
|---|---|---|
| 1 | Standalone crash-safe checkpoint/resume | Full carry and forcing/physics clocks, no lost or duplicated history, controlled end-time extension |
| 2 | Actual cluster-capable multi-GPU interfaces | Real launch/partition/exchange/distributed-checkpoint APIs; qualify actual operators through virtual ranks. Independent cases first, large-domain decomposition second |

| 7 | Lake model | Warm/freezing/snow/ice/thaw evidence on a representative user case |

Cluster qualification will use correctness simulation of actual operators,
virtual ranks and distributed failure/recovery, separately from predictive
communication cost models. Scenarios cover 4/8/16/64 virtual GPUs with
NVLink/PCIe and inter-node topology, bandwidth, latency and overlap sensitivity.
**Real-cluster speed and energy are unmeasured. No rental or paid hardware
execution is authorized by this plan.** Simulation-qualified interfaces are
not a measured multi-GPU performance claim.

New enabled features require original/pristine WRF evidence and affected
coupled, finite-value, output and restart gates. Proved bit-identical changes
reuse numeric evidence; changed numerics repeat affected gates once on the
final composition. v0.3.3's actual final residual ledger and source-specific
qualifications carry forward with their real status. The priority ranking
after restart/clusters is an owner judgement, not a popularity measurement.
